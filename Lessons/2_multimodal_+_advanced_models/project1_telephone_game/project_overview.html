Project 1: The Multimodal Telephone Game

With a partner, you will build a chain of AI models that passes a message from image to text to speech and back to an image, again and again, then measure exactly how and where the meaning drifts. At the end, the whole class plays one giant game of telephone across every team's models.

Weight: 20% of your final grade
Team size: 2 students (see Teams, Milestones, and Submission)
Length: about 3 weeks, with three Gradescope submissions and a live Game Day
Environment: Google Colab with a free GPU, using open models from Hugging Face
Starter notebook: project1_telephone_game.ipynb

This project ties together the whole module. The Multimodal Models lessons explained how models convert between modalities and what gets lost; the audio and image deep dives explained how the generators work. Now you will build a working multimodal pipeline, run controlled experiments on it, and explain the results.

1. The Game

In the children's game of telephone, a message is whispered from person to person, and the version that comes out the end is often very different from the one that went in. In this project, the "people" are AI models, and each one passes the message to the next in a different modality.

Run several rounds and you get a chain: the original image, then every caption, audio clip, transcript, and new image along the way. Your job is to build the chain, measure it, and explain it.

2. What You Will Build

Part A: Four stations

Each station is one Python function with a fixed interface, so that any team's station can plug into any other team's chain. The starter notebook defines these signatures and a check_stations() function that tests them.

You may use any open model for any station, and you are encouraged to try more than one. The starter models are small enough for a free Colab GPU and are tested with the notebook.

Part B: The game loop

Write run_telephone(start_image, rounds), which plays the game and records every artifact from every round. Save each chain with the provided save_chain() helper, which writes the standard file format used on Game Day.

Part C: Measure the drift

Run your chain on at least 5 starting images for at least 5 rounds each. Choose varied images: for example a simple object, a busy street, a face-free indoor scene, an image with text in it, and an unusual or surprising scene. Use your own photos or openly licensed images, and credit any you did not take.

For every round, compute the metrics from Chaining Models and What Gets Lost. The notebook provides the metric functions; your job is to use them well.

  • Word error rate between each caption and its transcript (how much the speech link loses).
  • Text similarity between each round's caption and the round-1 caption (how far the meaning drifts).
  • CLIP image similarity between each round's new image and the original (how far the picture drifts).

Plot drift against round number for each starting image, and identify which station causes the most loss.

Part D: Two extensions

Complete two of the following, one led by each partner. Each extension must include a measured comparison against your Part C baseline, not just a demo.

  1. Model showdown. Replace one station with a different model, such as SmolVLM instead of BLIP or whisper-small instead of whisper-base, and compare drift on the same starting images. Is the bigger model worth its extra time?
  2. Slow the drift. Design an intervention that keeps more meaning and show that it works. Ideas: ask a vision-language model for a more detailed caption, generate several images per round and keep the one with the highest CLIP similarity to the transcript, or fix the random seed.
  3. The sound route. Add a non-speech branch: turn the caption into music or sound effects with MusicGen, then recover a description with CLAP by scoring a candidate list you design. Compare it with the speech route.
  4. A noisy line. Add background noise to the audio at several loudness levels before the Listen station, and measure how WER and final image drift change. Where does the chain break?
  5. Your own idea. Propose it in your Milestone 0 plan; it must be approved by course staff.

3. Game Day

Game Day is a live class session where every team's stations join one long chain.

  1. Staff arrange the teams in a ring and assign each team one station.
  2. Staff give the first team a secret starting image. Each team runs only its assigned station on the file it receives, then uploads its output to the shared Game Day folder for the next team.
  3. After the message has gone all the way around, the class sees the original and the final result side by side and traces where the meaning changed.
  4. Each team then runs its own full chain on a second mystery image and reports its final CLIP similarity. Small prizes go to the most faithful chain and, by class vote, the best drift story.

Because files pass between teams, every team must read and write the standard formats exactly:

ArtifactFormat
ImagePNG, 512 × 512 pixels, RGB
AudioWAV, mono, 16,000 Hz, 16-bit
TextUTF-8 .txt file, at most 60 words

The notebook's run_station_on_file() helper reads and writes these formats for you. Test it before Game Day; a team whose files cannot be read breaks the chain for everyone after it.

5. Rules and Tips

  • Models: any open model from Hugging Face is allowed. Paid APIs are not required; if you use one for an extension, report its cost.
  • AI assistants: allowed for writing and debugging code, following the Generative AI Use Policy. Your report's analysis must be your own writing, and it must say how you used AI tools.
  • Images: do not use photos of people without their permission, and keep all content appropriate for class. Credit every image you did not create.
  • Compute: load each model once and reuse it, use the GPU runtime, and test on one image before running everything. With the starter models, one round takes a few seconds on a Colab T4 GPU.
  • Save as you go: Colab sessions reset. Save chains to Google Drive so you do not lose results.
