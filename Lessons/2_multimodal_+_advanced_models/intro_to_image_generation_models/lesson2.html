Learning a Shared Space: Contrastive Vision-Language Learning (CLIP)

1. Two encoders, one space

CLIP has two separate networks. An image encoder (a ViT or a ResNet) and a text encoder (a transformer) each produce one vector. A learned linear layer on each side maps those vectors to the same size \(d\) (for example \(512\)), and both are scaled to unit length.

image → image encoder → linear → normalize → u (d,) caption → text encoder → linear → normalize → v (d,) similarity(image, caption) = u · v (cosine similarity, since both have length 1)

Because the vectors are unit length, their dot product is the cosine of the angle between them: close to \(1\) for a good match, near \(0\) for unrelated content.

2. The contrastive objective

Take a batch of \(N\) image-caption pairs. Encode all of them to get image vectors \(\vec{u}_1, \dots, \vec{u}_N\) and text vectors \(\vec{v}_1, \dots, \vec{v}_N\). Form the \(N \times N\) grid of scaled similarities:

\[ s_{ij} = \frac{\vec{u}_i \cdot \vec{v}_j}{\tau} \]

Here \(\vec{u}_i \cdot \vec{v}_j\) is the cosine similarity between image \(i\) and caption \(j\), and \(\tau\) (the Greek letter tau) is the temperature: a positive number that the similarities are divided by. Dividing by a small \(\tau\) stretches the similarities apart, so \(s_{ij}\) is just a rescaled cosine similarity. Section 3 explains what this rescaling does and why it is needed.

In this grid, each row is one image and each column is one caption: row \(i\) holds the scores of image \(i\) against all \(N\) captions, and column \(j\) holds the scores of caption \(j\) against all \(N\) images. The true pairs sit on the diagonal (\(i = j\)). Every other cell is a mismatched pair, used as a negative. Each row is treated as a classification problem: "which of the \(N\) captions belongs to this image?" Each column asks the reverse: "which of the \(N\) images belongs to this caption?" The loss is the cross-entropy of both, averaged, which is why it is called symmetric:

\[ \mathcal{L}_{i \to t} = -\frac{1}{N} \sum_{i=1}^{N} \log \frac{e^{s_{ii}}}{\sum_{j=1}^{N} e^{s_{ij}}} \qquad \mathcal{L}_{t \to i} = -\frac{1}{N} \sum_{j=1}^{N} \log \frac{e^{s_{jj}}}{\sum_{i=1}^{N} e^{s_{ij}}} \] \[ \mathcal{L} = \tfrac{1}{2} \left( \mathcal{L}_{i \to t} + \mathcal{L}_{t \to i} \right) \]

The CLIP paper gives the whole loss in a few lines of pseudocode. Here it is written out step by step:

# image_emb: (N, d)   row i is the vector for image i, scaled to length 1
# text_emb:  (N, d)   row j is the vector for caption j, scaled to length 1
# tau:       the temperature, a positive number

# Step 1: cosine similarity of every image with every caption
sims = image_emb @ text_emb.T              # (N, N), sims[i][j] = image i vs caption j

# Step 2: divide by the temperature to get the scores s_ij
logits = sims / tau                        # (N, N)

# Step 3: the correct caption for image i is caption i,
# so the correct column in row i is i
labels = [0, 1, 2, ..., N-1]

# Step 4: image to text. Each ROW is one classification problem.
loss_i2t = cross_entropy(logits, labels)

# Step 5: text to image. Each COLUMN is one problem, so transpose first.
loss_t2i = cross_entropy(logits.T, labels)

# Step 6: average the two directions
loss = (loss_i2t + loss_t2i) / 2


def cross_entropy(logits, labels):
    total = 0
    for k in range(N):                     # go through the rows one at a time
        p = softmax(logits[k])             # N probabilities that add up to 1
        total += -log(p[labels[k]])        # -log of the probability of the correct entry
    return total / N                       # average over the N rows

CLIP's own code stores the temperature as a learned log-scale number t and multiplies the similarities by exp(t). That is the same as dividing by \(\tau\) with \(\tau = e^{-t}\).

The correct entry is caption 1, so the loss for this row is \(-\ln 0.881 \approx 0.127\). For image 2, the row \((0.5, 2.5)\) gives probabilities \(\approx (0.119,\ 0.881)\). The correct entry is caption 2, so this loss is also \(-\ln 0.881 \approx 0.127\). Average of the rows: \(\mathcal{L}_{i \to t} \approx 0.127\).

Step 3: text to image (go down each column). For caption 1, the column \((3, 0.5)\) gives probabilities \(\approx (0.924,\ 0.076)\) over the two images. The correct entry is image 1, so the loss is \(-\ln 0.924 \approx 0.079\). For caption 2, the column \((1, 2.5)\) gives \(\approx (0.182,\ 0.818)\). The correct entry is image 2, so the loss is \(-\ln 0.818 \approx 0.201\). Average of the columns: \(\mathcal{L}_{t \to i} \approx 0.140\).

Step 4: average the two directions. \(\mathcal{L} = \tfrac{1}{2}(0.127 + 0.140) \approx 0.134\).

What this shows. Caption 2 lost more than caption 1 because image 1 is a fairly good match for it too (score \(0.10\) against \(0.25\)), so the model was less sure. Training would push the diagonal scores up and the off-diagonal ones down, which lowers the loss. The temperature matters too: with \(\tau = 1\) the same grid gives a loss of about \(0.60\), because the scores \(0.30\) and \(0.10\) are too close together for the softmax to be confident. Dividing by a small \(\tau\) is what lets a modest gap in cosine similarity count as a clear win.

3. Temperature scaling

The temperature \(\tau\) rescales the similarities before the softmax. Cosine similarities live in a narrow range (all between \(-1\) and \(1\)), so without scaling the softmax would be almost flat and the loss could not tell a good match from a mediocre one.

  • Small \(\tau\) sharpens the softmax. Confident matches get probability near \(1\), and the gradient concentrates on the hardest negatives, the wrong captions that look nearly as good as the right one.
  • Large \(\tau\) flattens the softmax. All negatives are treated similarly and the signal is weak.

CLIP does not fix \(\tau\). It learns it, as a log-scale parameter initialized to \(\tau = 0.07\), and clips it so the logits are never scaled by more than \(100\).

If this sounds like the temperature setting for language models, that is because it is the same operation. In both cases the scores are divided by a temperature before the softmax, so a low value makes the probabilities sharper and a high value makes them flatter. The difference is when it is used. A language model applies temperature while generating, to control how random the next token is. CLIP uses it while training, to control how sharply the loss separates the correct caption from the wrong ones, and it learns the value instead of having you pick it.

4. Batch size

In a batch of \(N\) pairs, every image has \(N - 1\) negative captions and every caption has \(N - 1\) negative images. Larger batches mean more negatives, and more of them are hard. CLIP trained with a batch of \(32{,}768\) pairs, so each step scored \(32{,}768^2 \approx 1.07\) billion pairs.

  • Too small a batch gives only easy negatives (a dog photo against a caption about a bridge), so the model learns little about fine distinctions.
  • The grid grows as \(N^2\). Large-batch training spreads the work over many GPUs and shares embeddings between them.
  • False negatives exist. Two different photos can both be well described by "a dog on a beach," yet the loss treats one as wrong. Large batches make this more likely.

Later work such as SigLIP replaces the softmax over the whole batch with an independent yes/no loss on each pair, which relaxes the dependence on very large batches.

5. Zero-shot inference

Once CLIP is trained, there are two main ways to use it for classification. This section defines zero-shot inference and compares it with a linear probe.

  • Zero-shot inference is how you use CLIP when you have category names but no labeled images. You turn each name into a caption, embed it with the text encoder, and pick the caption closest to the image. The classifier is built from the names alone, with no training on your categories.
  • A linear probe takes the opposite route. First, you freeze the image encoder, meaning its weights never change, and run your labeled images through it to get one feature vector per image. Then you train a single linear classifier on those vectors so that it learns to map CLIP's features to your categories. It needs labeled images, but the only part that is trained is one small layer.

We start with zero-shot. As a formula, the predicted class \(\hat{y}\) for an image vector \(\vec{u}\) is the one whose caption vector \(\vec{v}_c\) is closest:

\[ \hat{y} = \arg\max_{c} \; \vec{u} \cdot \vec{v}_c \qquad \text{where } \vec{v}_c = f_{\text{text}}\big(\text{"a photo of a } c\text{"}\big) \]

The text embeddings \(\vec{v}_c\) act as the weights of a classifier that you built from words alone. Prompt wording matters: "a photo of a dog" usually beats the bare word "dog," and averaging the embeddings of several templates (prompt ensembling) helps further.

Zero-shot versus linear probing

A linear probe is the standard way to measure how good an encoder's features are, and it is the main alternative to zero-shot. You keep the image encoder frozen, meaning its weights never change. You run each labeled training image through it to get one vector \(\vec{u}\), and then train a single linear layer on top (the same kind of classifier as logistic regression):

\[ \hat{y} = \arg\max_{c} \, (W \vec{u})_c \qquad W \in \mathbb{R}^{C \times d} \]

Here \(C\) is the number of classes and \(d\) is the length of \(\vec{u}\), so \(W\) has one row per class. It is called a probe because you are checking what information the frozen features already contain, and linear because only one matrix is trained, so a good result has to come from the features rather than from a powerful new classifier on top. Compare this with zero-shot: there, the rows of the classifier are the text embeddings \(\vec{v}_c\), which need no training, while in a linear probe the rows of \(W\) are learned from labeled images.

Zero-shotLinear probe
What is trainedNothing newA linear classifier on frozen image features
Labeled images neededNoneSome per class
New categoriesJust write new captionsRetrain the classifier
Accuracy on a fixed taskGood, limited by wording and domainUsually higher once you have labels

Zero-shot CLIP is strong when your categories are common things people caption on the web. It is weaker on specialized domains (medical images, satellite imagery), on counting, and on fine-grained categories where the caption words are rare.
