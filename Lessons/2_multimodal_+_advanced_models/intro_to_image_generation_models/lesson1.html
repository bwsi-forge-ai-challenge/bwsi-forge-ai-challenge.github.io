In Computer Vision you usually feed an image into a network and get a label out — “cat,” “stop sign,” “tumor / not tumor.” Image generation flips that arrow. You start from a tiny list of numbers and expand it into a full picture.

You’ve already seen the cousin of this idea in audio. A neural codec compressed a long waveform into discrete tokens, then a decoder stretched those tokens back into sound. Images do something similar: compress into a compact latent, generate in that small space, then decode to millions of pixels. This lesson builds the pixel grid and the latent “blueprint” so later GAN and diffusion pages have somewhere to land.

1. An image is a 3D grid of numbers

A digital photo is not “a picture” to a computer. It is a tensor:

shape = (Height, Width, Channels)
  • Height × Width — how many pixels (a 512×512 image has 262,144 spatial locations).
  • Channels — usually 3 for RGB (red, green, blue). Each channel is an intensity from 0 (off) to 255 (full).
Worked example. One pixel that looks orange might be stored as [255, 140, 0]. A grayscale thumbnail ignores color and uses one channel: each cell is just brightness 0–255.

A 256×256 RGB photo stores 256 × 256 × 3 = 196,608 numbers. At one byte per channel that is already ~192 KB before JPEG compression — and generation models often target 512×512 or larger.
phone camera JPEG → decode to RGB array shape (H, W, 3), dtype uint8 → (often) scale to floats in [0, 1] or [-1, 1] for the network → for generation we will eventually output that grid again

Check your knowledge: pixel budget

Question: How many numbers does a 64×64 RGB image contain? A 512×512 RGB image?

Show answer

64×64×3 = 12,288. 512×512×3 = 786,432. Roughly 64× more numbers when you go from 64 to 512 on each side (because both height and width scale).

2. Why we don’t generate every pixel from scratch with one giant list

In the audio unit you saw why predicting 44,100 waveform samples per second is painful. Images have the same problem: a transformer that tried to emit 786,432 RGB values one-by-one would be absurdly long.

So modern image generators work in a latent space — a much smaller vector (or small spatial map) that still carries the important structure of the picture. A decoder / upsampler expands that compact code into the full pixel grid.

3. Latent space as a blueprint

Think of a latent vector z as a short address in a huge “neighborhood of possible images.” Nearby addresses tend to look related (same pose, similar lighting). Far-away addresses look like different scenes.

Metaphor: Turning a tiny 2D house blueprint into a full 3D house. If the blueprint is missing fine lines, the built house looks blocky, blurry, or warped — the same failure mode you get from a weak decoder or an undersized latent.

A minimal generative sketch:

  1. Sample or predict a small latent z (say length 16, or a 4×4×c feature map).
  2. Pass z through learned layers that upsample spatially (or decode from a bottleneck).
  3. Emit an image tensor of shape (H, W, 3).
z ∈ ℝd  →  Decoder / Generator  →  x ∈ ℝH×W×3
Toy numbers. Suppose d = 3 and we decode to an 8×8 grayscale patch (64 pixels). Each of the 3 latent numbers mixes into all 64 outputs through learned weights — change one coordinate and the whole pattern can shift. That is the intuition the sandbox below makes visible. Real models use much larger d (or spatial latents like Stable Diffusion’s ~64×64×4 map for a 512×512 image — about 48× fewer values than full RGB).

Check your knowledge: compression

Question: Stable Diffusion often generates in a latent that is 8× smaller on each spatial side than the final image (plus fewer channels). Why does that help generation?

Show answer

Fewer numbers to denoise / generate per step → cheaper compute and shorter effective sequences, while the VAE decoder restores high-resolution RGB detail — same spirit as audio codecs shrinking waveforms before the language model runs.

Check your knowledge: direction of the arrow

Question: Classifier CNNs map image → label. Generators map latent → image. Which direction does a VAE encoder travel, and why do diffusion models still use one?

Show answer

Encoder: image → latent (compression). Diffusion models often denoise in that compressed latent space so each step is cheaper; the decoder returns to pixels at the end — matching the audio “generate tokens, then decode” pattern.
