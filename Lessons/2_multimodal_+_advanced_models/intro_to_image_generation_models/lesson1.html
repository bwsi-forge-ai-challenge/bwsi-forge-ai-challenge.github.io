From Pixels to Tokens: Vision Encoders and Patchification

1. From CNN backbones to Vision Transformers

For a decade, the standard vision backbone was the convolutional neural network. A CNN slides small filters across the image and stacks layers so that edges become textures, textures become parts, and parts become objects. Two assumptions are built into the design: nearby pixels matter most (locality), and a pattern means the same thing wherever it appears (translation equivariance).

A Vision Transformer (ViT) drops both assumptions and uses a standard transformer. The image becomes a sequence of tokens, and self-attention lets every token look at every other token from the very first layer.

CNN backboneVision Transformer
Basic unitPixel neighborhood under a filterPatch token
Built-in assumptionsLocality, translation equivarianceAlmost none; learned from data
Reach of one layerSmall window; grows with depthWhole image from layer 1
Data appetiteWorks well on modest datasetsNeeds large datasets to beat CNNs
OutputFeature maps (often several scales)One vector per token

The last row matters for this unit. A sequence of vectors is exactly what a language model already knows how to read, which is why transformer encoders became the default front end for vision-language models.

2. Patch extraction

ViT turns an image of size \(H \times W \times C\) (height, width, color channels) into tokens in three steps.

  1. Cut the image into non-overlapping \(P \times P\) patches, where \(P\) is the patch size. The number of patches is \(N = \frac{H}{P} \cdot \frac{W}{P}\).
  2. Flatten each patch into a column vector \(\vec{x}_i \in \mathbb{R}^{P^2 C}\), where \(i = 1, \dots, N\) numbers the patches. The vector simply lists all \(P \cdot P \cdot C\) pixel values of patch \(i\).
  3. Project every flattened patch with the same learned matrix \(E \in \mathbb{R}^{D \times P^2 C}\) to get a token \(\vec{z}_i \in \mathbb{R}^{D}\), where \(D\) is the token width that the transformer works with.
\[ \vec{z}_i = E\,\vec{x}_i \qquad i = 1, \dots, N \]

The size rule for matrix products applies: \((D \times P^2 C)(P^2 C \times 1) = (D \times 1)\). The inner dimensions match, so a patch vector of length \(P^2 C\) becomes a token of length \(D\). The same \(E\) is used for every patch, and its entries are learned during training.

Notation note. Here vectors are columns and the matrix multiplies on the left (\(E\vec{x}_i\)). The ViT paper uses row vectors and multiplies on the right, writing \(\vec{x}_i^{\top} E_{\text{paper}}\) with \(E_{\text{paper}} \in \mathbb{R}^{P^2 C \times D}\). It is the same computation, because \(E_{\text{paper}} = E^{\top}\). Deep learning code usually stacks the \(N\) tokens as rows, which gives an \(N \times D\) array.
Worked numbers. A \(224 \times 224 \times 3\) image with \(P = 16\) gives \(N = 14 \cdot 14 = 196\) patches. Each patch vector \(\vec{x}_i\) has \(16 \cdot 16 \cdot 3 = 768\) entries. With \(D = 1024\) (ViT-Large), \(E\) is a \(1024 \times 768\) matrix, so each token \(\vec{z}_i\) has \(1024\) entries. All \(196\) tokens stored as rows form a \(196 \times 1024\) array.

In code, steps 1 to 3 are a single strided convolution whose kernel size and stride both equal \(P\). That is why you will often see the patch embedding written as Conv2d(3, 1024, kernel_size=16, stride=16).

3. Positional encodings in 2D

Self-attention has no sense of order. If you shuffled the patches and shuffled their positions together, the output would not change, so the model needs to be told where each patch came from.

The simplest fix, used by the original ViT, is to number the patches and give each number its own vector. Patches are numbered in reading order: left to right along the first row, then along the next row, and so on (this is called raster order). On a \(14 \times 14\) grid, patch \(1\) is the top-left corner, patch \(14\) ends the first row, and patch \(15\) sits directly below patch \(1\).

The model keeps a table with one vector \(\vec{p}_i \in \mathbb{R}^{D}\) for each patch number \(i\). These vectors are learned (also called trainable): they are parameters that start with random values and are adjusted by gradient descent during training, just like the weights in \(E\). Each position vector is added to the token of the matching patch before the transformer sees it:

\[ \vec{h}_i = \underbrace{\vec{z}_i}_{\text{from the pixels}} + \underbrace{\vec{p}_i}_{\text{from the position}} \]

Here \(\vec{h}_i \in \mathbb{R}^{D}\) is the input token for patch \(i\) that the transformer actually receives. The vector \(\vec{z}_i\) depends only on what the patch looks like, and \(\vec{p}_i\) depends only on where the patch is. Both have length \(D\), so they can be added entry by entry.

Nothing in these vectors says that patch \(15\) is below patch \(1\). The model works that out from data, because it ends up giving nearby grid positions similar vectors. The original transformer instead used fixed sinusoidal position codes; ViT simply learns its position vectors.

4. Self-attention over visual tokens

Once the tokens exist, the transformer treats them like words. Each layer computes attention between every pair of tokens:

\[ \text{Attention}(Q, K, V) = \text{softmax}\!\left( \frac{Q K^{\top}}{\sqrt{d_k}} \right) V \]

With \(N\) tokens, \(QK^{\top}\) is an \(N \times N\) matrix, so the cost grows with \(N^2\). At \(P = 16\), a \(224 \times 224\) image has \(196\) tokens and about \(196^2 = 38{,}416\) pairs per head. A \(384 \times 384\) image has \(576\) tokens and \(331{,}776\) pairs, which is about \(8.6\) times as many pairs for about \(2.9\) times as many pixels. This quadratic growth is the main reason high-resolution images and, later, video are expensive.

Two outputs are used downstream. A single summary vector for the whole image can be read out, for example by averaging the tokens, and this is what a classifier uses. The full sequence of patch tokens keeps spatial detail, and this is what most vision-language models pass to the language model.

5. Beyond vanilla ViT: Swin and ConvNeXt

Plain ViT has two weak spots from the last section: attention over all \(N\) tokens costs \(N^2\), and it produces features at only one resolution. Two later models address these in different ways.

Swin Transformer: attention in small windows

Swin keeps the transformer but limits each token's attention to a small window of nearby tokens (for example \(7 \times 7 = 49\) tokens). The cost then grows in proportion to the number of tokens instead of its square. Alternate layers shift the window grid by a few patches, so information can still cross window borders. Between stages, each \(2 \times 2\) group of neighboring tokens is merged into one, so the token grid shrinks like the feature maps in a CNN. For a \(224 \times 224\) input it goes from \(56 \times 56\) to \(28 \times 28\), then \(14 \times 14\), then \(7 \times 7\).

ConvNeXt: a CNN that borrows from transformers

ConvNeXt asks whether the transformer's success came from attention itself or from other design choices. It starts from a standard ResNet and adopts transformer-era ideas one at a time, for example cutting the image into non-overlapping \(4 \times 4\) patches at the very start and using larger filters. The result matches Swin at a similar size while using only convolutions, which suggests that patchification and overall design matter as much as attention.
