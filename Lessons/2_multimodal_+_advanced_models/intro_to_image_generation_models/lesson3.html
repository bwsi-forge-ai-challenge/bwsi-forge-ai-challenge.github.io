Teaching a Language Model to See: Vision-Language Models

1. The recipe: encoder, connector, language model

A language model reads a sequence of token embeddings (vectors) and writes text one token at a time, where each new token is chosen using everything that came before it. This is what autoregressive means. A plain language model cannot take in an image, because it only knows how to read vectors that look like word embeddings. A vision-language model (VLM) solves this by turning the image into vectors that sit alongside the word embeddings, so the language model can read the picture and the question together.

Almost every VLM is built from three parts:

PartIts jobShape in to shape outExample (LLaVA-1.5)
Vision encoderTurn the image into feature vectors, one per patch\(336 \times 336 \times 3\) image to \(N = 576\) vectors of width \(d_{\text{vision}} = 1024\)CLIP ViT-L/14 (a ViT-Large with \(14 \times 14\) patches)
ConnectorTranslate those features into the language model's embedding space\(576 \times 1024\) to \(M = 576\) visual tokens of width \(d_{\text{llm}} = 4096\)Two-layer MLP
Language modelRead visual tokens and text tokens together, then generate the answer\((M + L)\) tokens of width \(4096\) to probabilities for the next tokenVicuna 7B

Here \(L\) is the number of text tokens in the prompt. The connector exists because the encoder and the language model were trained separately and speak different "languages". Their vectors have different lengths (\(1024\) and \(4096\)), and, more importantly, the language model has never seen a CLIP feature, so it would not know what to do with one. The connector is trained to map each visual feature to a vector that lands in the right place among the word embeddings.

2. Projection layers

A language model only understands vectors of its own embedding size, so the connector's first job is dimension matching. Its second job is deciding how many tokens to pass along.

ConnectorWhat it doesTokens outUsed by
Linear adapterOne matrix: \(\vec{h}_v = W \vec{z}_v\)Same as in (\(N\))LLaVA
MLPTwo layers with a nonlinearity such as ReLU in between: \(\vec{h}_v = W_2\, \text{ReLU}(W_1 \vec{z}_v)\)Same as in (\(N\))LLaVA-1.5
Q-FormerA small transformer with \(32\) learned query vectors that cross-attend to the image featuresFixed at \(32\)BLIP-2
Perceiver ResamplerLearned latent queries cross-attend to the image featuresFixed at \(64\)Flamingo

The last two use learned queries: a fixed set of vectors that ask the image "what is worth keeping?" using cross-attention, \(\text{CrossAttn}(Q_{\text{learned}}, K_{\text{image}}, V_{\text{image}})\). The output size is set by the number of queries, not by the image size. That is useful for high-resolution images or many video frames, at the price of throwing detail away.

The trade-off is token count against detail. Passing all \(576\) tokens keeps small objects and printed text readable but fills the context window. A Q-Former's \(32\) tokens are cheap but cannot hold fine detail.

3. Token injection

Once the visual tokens exist, there are two ways to give them to the language model.

Input-level concatenation

The visual tokens are placed directly in the input sequence, next to the text tokens, and the language model's ordinary self-attention reads them. The prompt contains a placeholder such as <image> that is replaced by the projected tokens before the first layer. To the language model, a picture is a few hundred extra tokens. LLaVA and PaLM-E work this way.

Cross-attention layers inside the model

New cross-attention layers are inserted between the layers of a frozen language model, and text positions attend to the visual tokens through them. Flamingo does this with gated layers whose gate starts at zero, so training begins from the original language model's behavior. This does not consume context length, but it needs new layers.

Training usually has two stages. First, only the connector is trained on image-caption pairs, with the encoder and the language model frozen, so visual tokens learn to land in the language model's embedding space. Second, the connector and the language model are fine-tuned on instruction data (questions and answers about images). The loss is the usual next-token loss, computed on the answer tokens only:

\[ P(y_t \mid y_{\lt t},\; \vec{h}_v,\; \vec{x}_{\text{text}}) \]

These split into two camps. Bolt-on models (LLaVA, BLIP-2, Flamingo) join separately trained parts and train only the connector, or the connector plus fine-tuning. Native models (Gemini and GPT-4o) are trained across modalities from the start, which costs far more data and compute.
