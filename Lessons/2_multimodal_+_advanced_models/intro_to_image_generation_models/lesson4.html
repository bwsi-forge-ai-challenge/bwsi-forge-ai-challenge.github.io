1. Text as a magnetic field on the denoiser

In Lesson 3 the denoiser predicted “slightly less noise” at every timestep. With conditioning, that prediction also asks: does this latent patch look like my prompt?

Your prompt is tokenized and run through a text encoder (often a frozen CLIP or T5 transformer). You get a sequence of embedding vectors — one per token — that capture meaning (“golden retriever,” “oil painting,” “backlit”). Those vectors do not paint pixels directly. They bias the denoiser’s internal features so regions that match the words get reinforced and mismatches get suppressed.

Metaphor: Imagine sculpting fog with a magnet labeled “castle.” Each denoise step is a gentle push; the text embedding is the magnet that keeps pulling the emerging shapes toward turrets and stone walls instead of random blobs.
εθ(xt, t, c)   where c = text embeddings from your prompt

At every diffusion step t, the noisy latent xt and the text condition c enter the network together. Change the prompt → change c → different denoising trajectory → different final image.

Check your knowledge: what moves?

Question: Does text conditioning happen once at the start, or at every denoise step?

Show answer

At every step. The text embeddings are cached, but cross-attention (or equivalent fusion) runs inside the U-Net/DiT on each forward pass — same spirit as MusicGen applying text c at every AR token step.

2. Cross-attention: image queries, text keys/values

Transformers you met in NLP use self-attention: every token talks to every token. In conditioned diffusion, the denoiser adds cross-attention layers:

  • Queries (Q) come from image feature maps inside the U-Net/DiT (“what am I looking at in this patch?”).
  • Keys (K) and Values (V) come from text token embeddings (“what words should I align with?”).
One head, cartoon numbers. A spatial location in the latent might attend to prompt tokens like this:

The image query blends those text values → features shift toward neon edges and face-like structure. Different spatial queries attend to different words (sky patch → “sunset,” foreground → “dog”).
# Inside one cross-attention block (conceptual) Q = W_q · image_features # from noisy latent pathway K = W_k · text_embeddings # from CLIP/T5 encoder V = W_v · text_embeddings Attn = softmax(Q K^T / sqrt(d)) # which words matter here? output = Attn · V + image_features

Check your knowledge: Q/K/V roles

Question: In cross-attention for image diffusion, where do queries come from, and where do keys and values come from?

Show answer

Queries from image/latent features; keys and values from text token embeddings. That lets each spatial location “look up” relevant words while denoising.

3. Classifier-free guidance (CFG) — brief

Training often randomly drops the text condition (replace with a “empty” embedding). At inference the model can run twice: once with your prompt, once unconditioned. Classifier-free guidance pushes the update toward the conditional prediction:

ε̂ = ε∅ + w · (εc − ε∅)

w is the guidance scale (often 7–12 in SD 1.5). Higher w → stronger prompt adherence, but too high → oversaturated colors, weird anatomy, or “burnt” contrast. You already saw the same linear blend on logits in Audio Lesson 4.

Trade-off: CFG is not free quality — it doubles (or more) compute per step and can amplify failure modes. Lesson 5 covers when prompts still lose to dataset bias even with high w.

4. Diffusion Transformers (DiT) — the 2024–2026 trend

Classic Stable Diffusion used a U-Net: convolutional layers with skip connections, good at local textures. Long, detailed prompts (many adjectives, relationships, counts) stress how much text can steer conv features.

Diffusion Transformers (DiT) replace the U-Net backbone with a transformer that patches the latent into tokens (like ViT). Cross-attention to text is native; scaling laws from LLMs transfer — bigger DiT + more data → better prompt following. SD 3, Flux, and many 2025–2026 systems use DiT-style backbones or hybrids.

High-level takeaway: U-Net = local paintbrush; DiT = global scene planner with text cross-attn at every layer. You still denoise a latent; the architecture that predicts noise changed. Conditioning via text embeddings is the constant.

5. Full shape trail: prompt → pixels

prompt: "a golden retriever in a sunlit castle courtyard, oil painting" → Tokenizer → token IDs (L,) → Text encoder (CLIP/T5) → text embeddings (L, d_text) [cached] → Sample random noise z ~ N(0,I) → latent x_T (h, w, c) For t = T … 1: → U-Net or DiT(x_t, t, cross_attn(text_emb)) predicts noise ε → Optional CFG blend with ε_∅ → Scheduler step → x_{t-1} → Final latent x_0 → VAE decoder → RGB image (H, W, 3)

Then code: Open a fresh Google Colab notebook. Enable a GPU runtime (Runtime → Change runtime type → T4 GPU) for reasonable speed. SD 1.5 is slow on CPU; for a quick CPU smoke test consider stabilityai/sd-turbo (few steps, lower quality).

  1. Install diffusers, transformers, accelerate, and safetensors.
  2. Load a text-to-image pipeline (example below uses SD 1.5).
  3. Set a prompt and negative prompt; run inference.
  4. Save result.images[0] to disk and display in the notebook.
  5. Experiment: change guidance scale, seed, and prompt adjectives — connect to §3 and the steering board.

Ready-to-paste Colab cell:

# Cell 1 — install (restart runtime if Colab asks)
!pip install -q diffusers transformers accelerate safetensors

# Cell 2 — generate
import torch
from diffusers import StableDiffusionPipeline

model_id = "runwayml/stable-diffusion-v1-5"
# CPU-friendly alternative (fewer steps): "stabilityai/sd-turbo"

pipe = StableDiffusionPipeline.from_pretrained(
    model_id,
    torch_dtype=torch.float16 if torch.cuda.is_available() else torch.float32,
    safety_checker=None,
)
pipe = pipe.to("cuda" if torch.cuda.is_available() else "cpu")

prompt = "a golden retriever in a sunlit castle courtyard, oil painting, detailed"
negative = "blurry, low quality, extra limbs"

generator = torch.Generator(device=pipe.device).manual_seed(42)

image = pipe(
    prompt,
    negative_prompt=negative,
    num_inference_steps=25,
    guidance_scale=7.5,
    generator=generator,
).images[0]

image.save("my_first_sd.png")
image
Shape trail in code: pipe(prompt=...) hides tokenization, text encoding, the denoise loop with cross-attention, and VAE decode — exactly the trail in §5. Parameters you touch map to concepts: guidance_scale → CFG weight; num_inference_steps → how many denoise iterations; generator seed → reproducible noise init.
