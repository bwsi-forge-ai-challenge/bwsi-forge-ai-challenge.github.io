Adding Time: Video and Action

1. Video as a tensor, and why it is expensive

A video is a tensor of shape \(T \times H \times W \times 3\): \(T\) frames, each an image. Consider a \(3\)-minute clip at \(30\) frames per second:

Worked numbers. \(180 \text{ s} \times 30 \text{ fps} = 5{,}400\) frames. A LLaVA-style model spends \(576\) tokens per frame, so the whole clip is \(5{,}400 \times 576 = 3{,}110{,}400\) tokens, far beyond the context window of nearly any model. Even sampling one frame per second leaves \(180 \times 576 = 103{,}680\) tokens.

Everything below is a way to bring that number down while keeping the information that matters for the question being asked.

3D convolutions

A 2D convolution slides a small filter (say \(3 \times 3\)) across one image. At each position it multiplies the pixels under the filter by the filter's weights and adds them up. A 3D convolution does the same but the filter also extends through time. A \(3 \times 3 \times 3\) filter covers a \(3 \times 3\) patch of pixels in \(3\) consecutive frames, so it can respond to things that change from frame to frame, such as an edge moving to the right.

\[ y_{t,i,j} = \sum_{\delta_t,\, \delta_i,\, \delta_j} w_{\delta_t, \delta_i, \delta_j} \; x_{t + \delta_t,\; i + \delta_i,\; j + \delta_j} \]

In this formula, \(x_{t,i,j}\) is the input value at frame \(t\), row \(i\), column \(j\), and \(y_{t,i,j}\) is the output at the same position. The numbers \(w_{\delta_t, \delta_i, \delta_j}\) are the filter's learned weights, and the offsets \(\delta_t, \delta_i, \delta_j\) say how far from the center to look: for a \(3 \times 3 \times 3\) filter each offset is \(-1\), \(0\) or \(1\), giving \(27\) weights (a \(3 \times 3\) filter has only \(9\)). The sum collects the weighted values from this small block of space and time.

Temporal self-attention

A space-time transformer first cuts the video into tubelets, for example \(16 \times 16\) pixels across \(2\) frames. If \(T'\) is the number of time steps and \(P\) the patches per frame, there are \(T' P\) tokens. Joint attention compares all of them with all of them, at a cost of about \((T'P)^2\). Divided attention (TimeSformer) attends over time at each patch location and then over space within each time step, which costs about \(T' P^2 + P\, T'^2\).

Worked numbers. Take \(T' = 8\) time steps and \(P = 196\) patches. Joint attention needs \((8 \cdot 196)^2 = 1568^2 = 2{,}458{,}624\) pairs per head. Divided attention needs \(8 \cdot 196^2 + 196 \cdot 8^2 = 307{,}328 + 12{,}544 = 319{,}872\), about \(7.7\) times fewer.

VideoMAE shows a different trick for pre-training: it hides about \(90\%\) of the tubelets and trains the model to reconstruct them. Videos are so redundant from one frame to the next that this is still learnable, and it makes training far cheaper.

3. Frame sub-sampling strategies

Neighboring frames are nearly identical, so most of them can be dropped. The question is which ones to keep.

StrategyHow it picks framesStrengthWeakness
Fixed rateOne frame every \(k\) seconds (for example \(1\) fps)Simple; covers the whole clip evenlyCost grows with length; can miss a short event
Fixed countExactly \(K\) frames, evenly spaced (for example \(8\), \(16\), \(32\))Predictable cost for any lengthSparse for long videos
Scene or keyframeKeep a frame when the content changes enoughSpends frames where something happensNeeds a change detector; fast motion can fool it
Query-awareScore frames against the question (for example with CLIP similarity) and keep the bestUses the question to focus the budgetExtra pass; misses what the question did not mention

4. Token pruning and the memory ceiling

After choosing frames, you can cut tokens further:

  • Pool within a frame. Average each \(2 \times 2\) block of patch tokens, turning \(576\) tokens into \(144\).
  • Drop static tokens. If a patch is nearly the same as the same patch in the previous frame, keep only one copy.
  • Merge similar tokens (as in Token Merging, ToMe), combining those with close embeddings.
  • Prune inside the language model. Visual tokens that later layers pay little attention to can be dropped from deeper layers.

Each of these trades detail for budget. Pooling and pruning hurt most on small objects, on-screen text, and fast actions.

Why memory is the real limit

During generation the model stores keys and values for every token in a KV cache. Its size is

\[ \text{KV bytes} = 2 \times L \times d \times b \times n_{\text{tokens}} \]

where \(L\) is the number of layers, \(d\) the model width, \(b\) the bytes per number, and the factor \(2\) covers keys and values. For a 7B model (\(L = 32\), \(d = 4096\), 16-bit numbers so \(b = 2\)) this is \(524{,}288\) bytes, about \(0.5\) MB, for every token.

Worked numbers. \(180\) frames at \(144\) tokens each is \(25{,}920\) tokens, which needs \(25{,}920 \times 524{,}288 \approx 13.6\) GB of KV cache. The 7B weights in 16-bit take about \(14\) GB. Together that is more than a \(16\) GB GPU holds, before counting the vision encoder and working memory.

5. Real-world challenges

  • Action segmentation. Rather than one label for the whole clip, the model must label every frame or segment (for example "crack egg," "stir," "pour") and place the boundaries. It needs dense, temporally precise outputs, and datasets such as Breakfast and 50Salads are used to measure it.
  • Video question answering (Video-QA). Questions often depend on order ("what did the person do after opening the door?") or on counting events. Benchmarks such as NExT-QA and ActivityNet-QA test this. A model that sees only a few sparse frames can answer appearance questions and fail on temporal ones.
  • Compute and memory ceilings. Token count, KV cache size, and latency all grow with video length, so the design problem is always a trade between coverage and cost.
