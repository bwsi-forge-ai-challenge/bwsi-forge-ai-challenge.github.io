Prerequisites: Lesson 6 - The Full ML Pipeline

Lesson 5 detailed the mechanics of optimization over a multi-layer perceptron via forward propagation and backpropagation steps. However, optimizing a model architecture in isolation is insufficient for production. Engineering a reliable machine learning system requires nesting the network inside a repeatable engineering pipeline: data ingestion, preprocessing, partitioning, training, validation, and testing. This lesson maps out these operational phases, exploring the standard 70/15/15 cross-validation split, feature scaling, and regularization techniques designed to bound generalization error over high-capacity models.

1. From Raw Data to Feature Vectors

Models only understand numbers, so we convert raw data into feature vectors.

  • A 16×16 image becomes a vector of 256 numbers
  • Categorical values are mapped to numbers

The typical pipeline is:

  1. Collect data
  2. Split into train / validation / test sets
  3. Clean and preprocess data
  4. Train model
  5. Validate performance
  6. Test final performance

Important: Never use test data during training or preprocessing.

2. Train / Validation / Test Split

We partition our input datasets three seperate sections. For most datasets, engineers widely implement a 70% training / 15% validation / 15% test split:

  • Training set (70%): Used to learn patterns. We use this data to compute loss gradients and update parameters.
  • Validation set (15%): Used to tune settings (also called hyperparameter) like learning rate, model size and so on.
  • Test set (15%): Used only once at the end to ensure we get an unbiased estimation of how our model behaves in the real world.

If we accidentally use test data during training, we get data leakage, which makes results look better than they really are.

3. Feature Normalization and Gradient Scaling

When input features are on very different scales—such as pixel values ranging from \([0, 255]\) and other features ranging from \([0, 1]\)-the learning process can become unbalanced. Features with larger values can overly influence the model, causing it to learn unevenly across dimensions. This can slow down learning or make optimization unstable.

Z-score standardization fixes this by rescaling each feature so they have a common scale:

\[ x_{\text{norm}} = \frac{x - \mu}{\sigma} \]

Here, \(\mu\) is the mean of the training data and \(\sigma\) is the standard deviation.

It is very important that \(\mu\) and \(\sigma\) are computed only from the training data, and then reused for validation and test data. This prevents information from leaking between datasets.

After standardization, all features are on a similar scale. This makes training more stable and helps the model learn at a similar rate across all features using a single learning rate.

For example, in a real estate model with 13 features, one feature might be the number of rooms (ranging from 3 to 9), while another might be local tax values (ranging from 200 to 700). Without scaling, the larger-valued feature would dominate learning. Standardization ensures both features contribute fairly to training.

4. Overfitting Dynamics and Learning Curves

Overfitting defines a state where a machine learning model fits very well to the training set but doesn't do so well on the validation set. This can happen because the model learnt the noise in the training set instead of understanding the actual underlying data distribution. This divergence can be easily seen when inspecting learning curves—plots tracking training and validation error metrics across training:

  • Convergent fit: Training and validation error metrics decline together, stabilizing near an acceptable loss floor.
  • Overfitting: Training error consistently falls toward zero while validation error flattens or even goes up. Training accuracy converges, whereas validation performance degrades.
  • Underfitting: Both error trajectories stabilize at unacceptably high baselines, indicating that the model size or training duration is insufficient to understand the data.

Large models overfit quickly when trained on a small datasets. The model uses its large parameter count to memorize individual training points rather than extracting generalized features.

Tracking training loss against validation loss across training steps serves as the primary indicator of this issue.

Source: Machine Learning: How to Prevent Overfitting

5. Regularization

L2 Regularization

Generalization error can be reduced by adding mathematical constraints that limit the capacity of the model’s individual weights.

L2 regularization adds a quadratic penalty to the loss function based on the squared values of all individual weights:

\(L_{\text{total}} = L_{\text{data}} + \frac{\lambda}{2} \sum_{l} \sum_{i} \left(w_i^{(l)}\right)^2\)

The hyperparameter \(\lambda\) controls how strong this penalty is. It pushes individual weight values toward zero and encourages smoother, lower-variance decision boundaries. During backpropagation, the gradient includes an extra term \(-\lambda w\), which effectively scales each weight down at every update. This is why L2 regularization is also called weight decay. By limiting how large individual weights can grow, the model is less likely to form overly complex, high-frequency decision boundaries that fit noise in the data.

Dropout

Large neural networks can sometimes become too dependent on specific neurons during training. When this happens, the model may memorize patterns in the training data instead of learning features that generalize well to new examples. Dropout is a regularization technique that randomly turns off a fraction of neurons during each training step.

The probablity with which we turn off neuron (or similarly the expected fraction of neurons which are turned off) \(p\) is called the dropout rate. For example, if \(p = 0.5\), then each neuron has a 50% chance of being temporarily turned off during a training step.

Because different neurons are removed at random each time, the network cannot rely too heavily on any single neuron. Instead, it must learn multiple ways to represent useful patterns in the data. This makes the model more robust and helps reduce overfitting. Note that dropout is only used during training. During inference (when making predictions), all neurons remain active so the full network can be used.

6. Learning Rate Dynamics and Convergence Stability

The scalar learning rate hyperparameter \(\alpha\) controls the size of each gradient update during training: \((\theta \leftarrow \theta - \alpha \nabla L)\). This parameter affects both normalization layers and regularization behavior, and plays a key role in determining whether training converges stably.

  • High rates: The optimization steps overshoot the minimum of the loss function, causing unstable oscillations or even divergence. Instead of smoothly decreasing, the loss fluctuates unpredictably.
  • Optimal rates: The model converges smoothly. Both training and validation loss decrease steadily toward a minimum.
  • Low rates: Updates become extremely small, making training very slow and potentially leaving the model far from an optimal solution even after many epochs.

Source: Learning Rate Machine Learning

Adaptive optimizers such as Adam or RMSprop adjust the learning rate automatically for each parameter, helping handle features with different scales. However, they still perform better when inputs are pre-standardized. In practice, the learning rate \(\alpha\) should be tuned using the validation set to minimize validation error, rather than focusing only on training loss.

Optimizer choice (e.g., SGD, Momentum, or Adam) is also a separate hyperparameter selected using validation performance. Adam often converges faster early in training with default settings, while carefully tuned SGD with momentum can achieve better generalization on large-scale problems. The general workflow remains the same: train on the training set, tune using validation, and evaluate once on the test set.
