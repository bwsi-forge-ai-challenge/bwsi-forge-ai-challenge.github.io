Recurrent Neural Networks & The Problem of Memory

Up until now, we have treated machine learning data as something fundamentally static. When we built MLPs and Convolutional Networks, we fed them isolated snapshots of data: a fixed grid of pixels or a single input vector. The model would compute its output, draw its boundary, and completely wipe its slate clean for the next input.

But many types of data are not static. The world around us is structured as continuous, evolving sequences. Think of the words you are reading right now, the sound waves of a music file, or the varying numbers of a stock index. In these formats, context is everything. The meaning of an element at step \(t\) depends entirely on what happened directly before it. To map these dependencies, computing frameworks require something new: an architectural memory footprint.

To represent this data, we introduce the Recurrent Neural Network (RNN). Developed as the original model for time-series and language tasks, the RNN attempts to handle data streams by passing an internal, evolving "hidden state" forward across time steps. In this post, we will look at how that loop works, why context matters for sequential data, and how later models (LSTMs, Transformers) solve the same problem with different machinery.

1. Why Feedforward Networks Struggle with Sequences

Suppose we want to predict the next word in a sentence using a standard feedforward network (MLP). If we feed the model only the current token, such as "sat", the network has no information about the words that came before it. It cannot tell whether the sentence began with "The fierce mountain lion..." or "The priceless antique vase...". Without context, many language tasks become much harder.

One possible solution is to provide several previous words along with the current one by concatenating them into a larger input vector. While this gives the model some context, it introduces a new problem: the input size grows with the length of the context window, and the model can only use information that fits within that fixed window.

Observable Inputs vs. Hidden Memory

To understand how an RNN works, it helps to separate the information provided by the dataset from the information maintained internally by the model:

  • Observable Input (\(x_t\)): The input vector at timestep \(t\). This could be a token embedding, an audio frame, or a sensor measurement.
  • Hidden State (\(h_t\)): The model's internal representation at timestep \(t\). It is not part of the input data; instead, it stores information accumulated from previous timesteps.
  • Output / Prediction (\(y_t\)): The model's prediction at timestep \(t\). In language modeling, this is typically a probability distribution over possible next tokens and is compared against the true next token during training.

The hidden state provides the model with a form of memory, allowing information from earlier parts of the sequence to influence later predictions.

2. Inside a Recurrent Cell

At each timestep \(t\), an RNN combines two pieces of information: the current input vector \(x_t\) and the hidden state from the previous timestep \(h_{t-1}\). The update is defined by the following equations:

\[ h_t = \tanh(W_h \cdot h_{t-1} + W_x \cdot x_t + b) \] \[ y_t = W_y \cdot h_t + b_y \]

The key detail is that the parameter matrices \(W_h\), \(W_x\), and \(W_y\) are reused at every timestep. This property is known as weight sharing.

Weight sharing allows the same computation to be applied across an entire sequence regardless of its length. As a result, an RNN uses the same set of parameters whether it processes a sentence containing 5 words or a document containing 5,000 words.

This idea is similar to the weight sharing used in convolutional neural networks, where the same kernel is applied repeatedly across different regions of an image.

Visualizing the Recurrent Update: At each timestep, the current input \(x_t\) and the previous hidden state \(h_{t-1}\) are combined to produce an updated hidden state \(h_t\). That hidden state is then used to generate the output \(y_t\).

3. Unrolling Time

To train an RNN with standard optimization methods, we use a conceptual tool called unrolling. When an RNN is unrolled across a sequence of length \(T\), it becomes equivalent to a feedforward network with \(T\) layers, where each layer shares the same parameters.

Unrolling removes the recurrent loop and lays the computation out across time. This makes it easier to see how information moves forward through a sequence and how gradients flow backward during training.

4. When RNNs Dominated Sequence Modeling

Before Transformers became the standard architecture, recurrent neural networks and their gated variants were the leading approach for sequence-based tasks. During the mid-2010s, they powered major advances in language and speech systems:

  • Machine Translation: In 2016, architectures like Google’s Neural Machine Translation (GNMT) replaced many traditional statistical translation systems with deep LSTM-based models. These networks encoded a source sentence into a learned representation and then generated a translation in the target language.
  • Speech Recognition: Early production voice assistants such as Siri and Google Assistant relied heavily on recurrent architectures to process audio streams and convert speech into text.
  • Character-Level Text Generation: Andrej Karpathy's influential post, The Unreasonable Effectiveness of Recurrent Neural Networks, demonstrated that even relatively simple RNNs could learn to generate text one character at a time, including code, Shakespeare-style writing, and structured documents.

5. The Main Limitation: Vanishing Gradients

Despite their elegance, vanilla RNNs struggle with long-range dependencies. Training an RNN requires an algorithm called Backpropagation Through Time (BPTT), which propagates gradients backward through every step of the unrolled sequence.

\[ \frac{\partial L}{\partial W_h} = \sum_{t=1}^T \frac{\partial L_t}{\partial h_t} \cdot \frac{\partial h_t}{\partial W_h} \]

The challenge comes from the recurrent connection itself. To determine how an early input affects a much later prediction, BPTT must repeatedly apply the chain rule through every intermediate timestep.

6. LSTMs and GRUs: A Better Memory Mechanism

To address the limitations of vanilla RNNs, researchers developed gated recurrent architectures, most notably the Long Short-Term Memory (LSTM) network and the Gated Recurrent Unit (GRU).

Rather than storing everything in a single hidden state, an LSTM introduces a dedicated memory pathway called the cell state (\(c_t\)). This pathway allows information to travel across many timesteps with less degradation, making long-range dependencies much easier to learn.

The flow of information through the cell state is controlled by three gates. Each gate uses a sigmoid activation to produce values between 0 and 1, determining how much information should be kept, added, or exposed:

  • Forget Gate (\(f_t\)): Decides which information should be removed from memory.
  • Input Gate (\(i_t\)): Determines which new information should be written into memory.
  • Output Gate (\(o_t\)): Controls how much of the cell state contributes to the hidden state \(h_t\).

The LSTM Information Highway: The cell state (top horizontal path) carries information across long distances, while the gates control what is forgotten, stored, and revealed at each step.

Here's how these approaches differ:

ArchitectureHow Context Is Handled
Vanilla RNNMaintains a single hidden state that is updated at every timestep. Simple, but struggles with long-range dependencies.
LSTM / GRUUses gated memory pathways to preserve information over longer sequences, but still processes tokens one step at a time.
Transformer (Next Unit)Uses self-attention to directly connect tokens across the sequence without relying on a recurrent loop.

7. From Recurrence to Attention

Recurrent models introduced one of the most important ideas in modern AI: next-token prediction. By training a model to predict what comes next in a sequence, we encourage it to learn patterns in language, structure, and meaning.

However, even LSTMs face an important limitation: they process information sequentially. Before computing timestep \(t\), the model must first compute timestep \(t-1\). This dependency makes training difficult to parallelize across modern hardware.

As datasets and model sizes grew, this sequential bottleneck became increasingly restrictive. The breakthrough came with the Transformer, which replaced recurrence with self-attention. Instead of processing tokens one at a time, Transformers allow every token to interact with every other token simultaneously, making large-scale training dramatically more efficient. We will introduce Transformers in the next module, Intro to Generative AI.
