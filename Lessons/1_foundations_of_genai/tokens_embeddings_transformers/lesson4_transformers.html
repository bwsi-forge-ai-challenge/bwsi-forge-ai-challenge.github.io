Transformers: Putting It All Together

Each of the last three lessons built one part of a language model: tokens, embeddings, and attention. This lesson connects them into one machine, the transformer, and follows a single sentence through it from raw text to the next word it predicts.

1. The Pieces You Already Have

Each lesson in this unit answered one question. Together they cover most of what a transformer does:

LessonPieceQuestion it answersInput → output
1. TokenizationTokenizerHow does text become numbers?text → list of token IDs
2. EmbeddingsEmbedding tableHow does a number carry meaning?token ID → vector of 768 numbers
3. AttentionSelf-attentionHow does a word use its context?vectors → context-aware vectors

Four things are still missing before these pieces can predict text:

  1. A feed-forward network that processes each word's vector after attention has mixed in context.
  2. Residual connections and normalization, which keep information and numbers stable as the vectors pass through many layers.
  3. Stacking: repeating attention and the feed-forward network many times.
  4. An output step that turns the final vector into a probability for every possible next token, plus a loop that turns one prediction into a whole paragraph.

The rest of this lesson adds those four pieces in the order the data flows through them.

2. The Whole Pipeline at a Glance

This diagram shows a GPT-style transformer, the kind behind ChatGPT, processing the prompt "The cat sat on the". Read it top to bottom. The shapes on the right follow the data; the labels on the right say which lesson introduced each step.

Notice what is not in the diagram: there is no separate grammar module, fact database, or reasoning engine. Every capability of the model comes from the numbers inside these boxes, learned during training.

3. Following One Sentence Through the Model

We will use GPT-2 small for every number in this section, because its size is public: a vocabulary of 50,257 tokens, vectors of 768 numbers, and 12 transformer blocks. Larger models use the same steps with bigger numbers.

Step 1: Tokenize the text (Lesson 1)

The tokenizer splits "The cat sat on the" into 5 tokens, "The" " cat" " sat" " on" " the", and replaces each with its integer ID. The leading spaces are part of the tokens, as Lesson 1 showed.

Shape: [5], five integers

Step 2: Look up an embedding for each token (Lesson 2)

The model owns an embedding table with one row per vocabulary entry: 50,257 rows of 768 numbers each. Each token ID selects its row. After this step the sentence is a grid of numbers, one 768-number vector per token.

Shape: [5 × 768]

At this point the vector for " sat" is the same no matter what sentence it appears in. Lesson 2 ended with this exact problem: the embedding for "bank" cannot tell a river bank from a financial bank. The next steps fix that.

Step 3: Add position information (Lesson 3, section 8)

Attention compares every token with every other token, so on its own it cannot tell "The cat sat on the" from "the on sat cat The". Each position (1st, 2nd, 3rd, …) therefore has its own position vector, which is added to the token's embedding. The original Transformer computed these with sine waves (the pattern shown in Lesson 3); GPT-2 learns them during training. Either way, the result has the same shape.

Shape: [5 × 768]. Each row now encodes which token and where it is.

Step 4: Run one transformer block

A transformer block is the repeating unit of the model. It has two main parts, each wrapped with an add-and-normalize step.

4a. Masked multi-head self-attention (Lesson 3). Every token builds a Query, Key, and Value, scores itself against the other tokens, and blends in the Values of the tokens that matter, exactly as in Lesson 3. GPT-2 small runs 12 attention heads side by side, each with its own 64-number Q, K, and V, and joins their outputs back into 768 numbers.

One rule is new: the attention is masked (also called causal). Each token may only look at itself and the tokens before it. " on" can attend to "The", " cat", and " sat", but not to " the". Section 6 explains why a text-generating model needs this rule.

4b. Feed-forward network (new). After attention has mixed context into each vector, every token's vector passes separately through the same small neural network: 768 numbers expand to 3,072, go through a nonlinear activation, then shrink back to 768. This is the multi-layer perceptron from the prerequisites, applied to one token at a time.

Attention and the feed-forward network have different jobs. Attention moves information between tokens. The feed-forward network transforms the information within each token, and it holds about two-thirds of each block's parameters. Research suggests much of the model's stored knowledge, such as facts about the world, lives in these feed-forward layers.

4c. Residual connections and normalization (new). Neither sub-step replaces the vector it receives. Each one computes a change that is added back onto its input:

\[ x \leftarrow x + \text{Attention}(x) \qquad x \leftarrow x + \text{FeedForward}(x) \]

This addition is a residual connection. It means information from earlier steps, such as the original word identity, is never lost; each block only adds refinements. It also gives the training signal a direct path back through many layers, which avoids the vanishing-gradient problem you saw with RNNs. Layer normalization rescales each token's vector to a consistent range, so the numbers neither explode nor shrink as they pass through dozens of blocks.

Shape in: [5 × 768] → shape out: [5 × 768]

Step 5: Repeat the block 12 times

Because a block's output has exactly the same shape as its input, the output of block 1 can feed block 2, and so on. GPT-2 small stacks 12 blocks; GPT-3 stacks 96. Each block has its own learned weights, so each can learn different patterns. Studies of trained models find that earlier blocks tend to capture local patterns such as grammar, while later blocks capture broader meaning, though the split is not strict.

After the stack, the vector for " bank" in "I deposited money at the bank" would differ from the one in "We fished from the river bank". This is the context-dependent meaning that Lesson 2 promised and Lesson 3 explained.

Step 6: Turn the last vector into probabilities (new)

To predict the next token, the model needs only the vector at the last position, " the". Because of the causal mask, that is the one position that has seen the entire prompt.

A final linear layer multiplies this 768-number vector by a matrix with one row per vocabulary token, producing 50,257 scores called logits, one for every possible next token. GPT-2 reuses the embedding table from Step 2 as this matrix, so a token scores high when the final vector points in a similar direction to that token's embedding. Softmax, the same function attention used in Lesson 3, turns the scores into probabilities that add up to 1:

\[ p_i = \frac{e^{z_i}}{\sum_{j} e^{z_j}} \]

Shape: [768] → [50,257] probabilities

Step 7: Pick a token and repeat (new)

The model now has a probability for every token, for example " mat" high, " floor" lower, " banana" near zero. A decoding rule picks one:

  • Greedy decoding always takes the most likely token. It is predictable but can be repetitive.
  • Sampling picks randomly in proportion to the probabilities. A setting called temperature controls how adventurous it is: low temperature favors the top choices, high temperature spreads the chances out. This is why a chatbot can give different answers to the same prompt, as you saw in the first unit.

The chosen token is appended to the input, "The cat sat on the mat", and the whole pipeline runs again to predict the token after that. This loop, one token at a time, is called autoregressive generation. It stops when the model produces a special end-of-text token or reaches a length limit. A 300-word answer is roughly 400 trips through the pipeline.

The whole lesson in one line: text → token IDs → embeddings + positions → 12 × (attention + feed-forward, each with add & normalize) → last vector → logits → softmax → next token → append and repeat.

Check your understanding: shapes

Question: GPT-2 small reads the 8-token prompt "Once upon a time there lived a". What is the shape after the embedding step, after all 12 blocks, and after the final linear layer?

Answer: [8 × 768] after embedding, still [8 × 768] after the blocks, since every block keeps the shape, and [50,257] logits for the last position.

5. Explore a Real Model: Transformer Explainer

The walkthrough above used made-up probabilities. Transformer Explainer runs the real GPT-2 small model, the one this lesson uses for every number, inside your browser. You can type a prompt and click into every box of the pipeline diagram to see the actual numbers.

Before you start

  • Use a laptop or desktop. On a phone you can only try the built-in examples.
  • The first visit downloads the model, which can take a minute.
  • Prompts are limited to 12 words. Click Generate to predict the next token.

Part 1: Tokens and embeddings (Lessons 1 and 2)

  1. Type The cat sat on the and click Generate. How many tokens does the tool show? Does that match Step 1 of this lesson?
  2. Click the Embedding section to expand it. Find where the token embedding and the positional encoding are added together. What is the length of each token's vector?
  3. Try a long or unusual word, such as unhappily or your own name. Does it stay one token or split into pieces? Compare with the tokenization you saw in Lesson 1.

Part 2: Attention (Lesson 3)

  1. Expand Multi-head Self Attention and find the Query, Key, and Value vectors. How many numbers is each one per head? Why is that 768 divided by the number of heads?
  2. Look at the attention matrix after the Scaling · Mask step. Why is the top-right half empty or grayed out? Connect your answer to the causal mask from Step 4a.
  3. Hover over the last token in the attention matrix. Which earlier tokens does it attend to most? Switch to a few different heads. Do different heads focus on different words?

Part 3: Feed-forward and blocks (this lesson)

  1. Expand the MLP. What size does each token's vector grow to, and what does it shrink back to? Check your answer against Step 4b.
  2. How many transformer blocks does the tool show stacked after the first one? Does that match GPT-2 small's 12?

Part 4: Probabilities and sampling (Steps 6 and 7)

  1. Look at the probability bars on the right. What are the top three next tokens for your prompt, and how likely is each one?
  2. Slide Temperature down to its lowest value, then up to its highest. What happens to the shape of the probability bars? Which setting would you use for a chatbot answering math questions, and which for brainstorming story ideas?
  3. Switch Sampling between Top-k and Top-p, and click Generate several times with the same prompt. Do you always get the same next token? Explain why, using what you learned about sampling in Step 7.
  4. Write a prompt where you expect GPT-2 to be confident (one tall bar) and one where you expect it to be unsure (many short bars). Were you right? What made the difference?

6. Training and Generation Use the Same Pipeline

During generation, the model runs the pipeline once per new token and uses only the last position's prediction. During training, it runs the pipeline once on a whole passage and uses every position's prediction at the same time:

PositionThe model seesIt must predict
1The cat
2The cat sat
3The cat sat on
4The cat sat on the
5The cat sat on the mat

One six-token sentence gives five training examples at once. This is why the causal mask matters: if position 3 could attend to position 4, it could read the answer instead of predicting it. With the mask, each position only knows what came before it, which is exactly the situation the model faces when it generates text.

The model's error at each position is measured with cross-entropy loss, which is low when the model gave the correct next token a high probability. Gradient descent then nudges every weight in the pipeline, the embedding table, every attention head, and every feed-forward layer, to reduce that loss. Processing all positions in parallel is a major reason transformers train much faster than RNNs, which must read one token at a time. The next unit, How Do LLMs Actually Learn?, picks up from here.

Check your understanding: the mask

Question: Suppose a model were trained without the causal mask on the table above. Its training loss drops close to zero, but it generates nonsense. Why?

Answer: Without the mask, each position can attend to the very next token, so the model learns to copy the answer rather than predict it. During generation the next token does not exist yet, so that shortcut is unavailable and the model has learned nothing useful.

7. Where the Parameters Live

"GPT-2 small has 124 million parameters" sounds abstract. Every one of those numbers sits in a specific box of the pipeline diagram:

Part of the pipelineCalculationParameters
Embedding table (Step 2; reused in Step 6)50,257 × 76838.6 M
Position vectors (Step 3)1,024 positions × 7680.8 M
Attention, per block (Step 4a)Q, K, V and output weights2.4 M
Feed-forward, per block (Step 4b)768 → 3,072 → 7684.7 M
All 12 blocks (Step 5)12 × 7.1 M85.1 M
Total≈ 124 M

Two things stand out. Nearly a third of GPT-2 small is the embedding table, simply because its vocabulary is large. And inside the blocks, the feed-forward networks hold twice as many parameters as attention.

Scaling up means making the same boxes bigger and repeating them more often. GPT-3 uses vectors of 12,288 numbers, 96 attention heads, and 96 blocks, for 175 billion parameters, with no new kind of box. The 1,024-position limit in the table is GPT-2's context window, the most tokens it can read at once. The next unit covers context windows and the cost of scaling in detail.

Check your understanding: parameter count

Question: A model uses vectors of 1,024 numbers instead of 768 but keeps GPT-2's 50,257-token vocabulary. How many parameters are in its embedding table?

Answer: 50,257 × 1,024 = 51,463,168, about 51.5 million.

8. Three Kinds of Transformer

Everything above describes a decoder-only transformer, the design used by GPT, Llama, and most of today’s chatbots. The same blocks can be arranged in two other ways, depending on whether the model needs to generate text, understand it, or both:

TypeAttentionGood atExamples
Decoder-onlyMasked: each token sees only earlier tokensGenerating text one token at a timeGPT, Llama
Encoder-onlyUnmasked: each token sees the whole inputUnderstanding and classifying text, searchBERT, MiniLM (the model in Lesson 3's visualizer)
Encoder-decoderEncoder unmasked, decoder masked and also attends to the encoderTurning one text into another, such as translationThe original 2017 Transformer, T5

The encoder diagrams in Lesson 3 came from the original translation Transformer, which is why they show an encoder. The blocks are the same; only the mask and the way they are connected differ.

Key Takeaways

  • A transformer is one pipeline: tokenize, embed, add positions, run a stack of identical blocks, and turn the last vector into next-token probabilities.
  • Each block pairs attention, which moves information between tokens, with a feed-forward network, which transforms each token on its own. Residual connections and normalization keep information and numbers stable through many blocks.
  • Every block keeps the shape [tokens × 768], which is what makes stacking possible.
  • Text is generated one token at a time: predict, append, repeat. The causal mask makes training match this situation.
  • Bigger models use the same boxes, made wider and repeated more often.
