Transformers: Putting It All Together

Each of the last three lessons built one part of a language model: tokens, embeddings, and attention. This lesson connects them into one machine, the transformer, and follows a single sentence through it from raw text to the next word it predicts.

1. What Is a Transformer?

A transformer is a kind of neural network designed to work with sequences, such as the tokens of a sentence. It was introduced in 2017 in the paper Attention Is All You Need, and almost every modern language model is built on it. The "T" in GPT stands for transformer: Generative Pre-trained Transformer.

Definition: A transformer is a neural network that turns a sequence of token embeddings into a sequence of context-aware vectors by passing them through a stack of identical blocks. Each block uses attention to let every token gather information from the other tokens, then a small feed-forward network to process each token on its own.

The key difference from the RNNs you saw in the prerequisites is how the model reads its input:

RNNTransformer
How it readsOne token at a time, in orderAll tokens at once
How tokens share informationThrough a single hidden state passed from step to stepThrough attention, where any token can look directly at any other
Long-distance connectionsCan fade as the hidden state is updated over many stepsJust as easy to make as short ones
Training speedSlow, because each step waits for the one before itFast, because every position can be computed in parallel

It also helps to separate two words that often get mixed up. The transformer architecture is the blueprint: which layers there are and how data flows between them. A transformer model, such as GPT-2 or Llama, is that blueprint with a specific size and a specific set of trained weights. This lesson walks through the blueprint, using GPT-2 small as the running example.

2. The Pieces You Already Have

Each lesson in this unit answered one question. Together they cover most of what a transformer does:

LessonPieceQuestion it answersInput → output
1. TokenizationTokenizerHow does text become numbers?text → list of token IDs
2. EmbeddingsEmbedding tableHow does a number carry meaning?token ID → vector of 768 numbers
3. AttentionSelf-attentionHow does a word use its context?vectors → context-aware vectors

Four things are still missing before these pieces can predict text:

  1. A feed-forward network that processes each word's vector after attention has mixed in context.
  2. Residual connections and normalization, which keep information and numbers stable as the vectors pass through many layers.
  3. Stacking: repeating attention and the feed-forward network many times.
  4. An output step that turns the final vector into a probability for every possible next token, plus a loop that turns one prediction into a whole paragraph.

The rest of this lesson adds those four pieces in the order the data flows through them.

4. Following One Sentence Through the Model

We will use GPT-2 small for every number in this section, because its size is public: a vocabulary of 50,257 tokens, vectors of 768 numbers, and 12 transformer blocks. Larger models use the same steps with bigger numbers.

Step 1: Tokenize the text

The tokenizer splits "The cat sat on the" into 5 tokens, "The" " cat" " sat" " on" " the", and replaces each with its integer ID. The leading spaces are part of the tokens, as Lesson 1 showed.

Shape: [5], five integers

Step 2: Look up an embedding for each token

The model owns an embedding table with one row per vocabulary entry: 50,257 rows of 768 numbers each. Each token ID selects its row. After this step the sentence is a grid of numbers, one 768-number vector per token.

Shape: [5 × 768]

At this point the vector for " sat" is the same no matter what sentence it appears in. Lesson 2 ended with this exact problem: the embedding for "bank" cannot tell a river bank from a financial bank. The next steps fix that.

Step 3: Add position information

Attention compares every token with every other token, so on its own it cannot tell "The cat sat on the" from "the on sat cat The". Each position (1st, 2nd, 3rd, …) therefore has its own position vector, which is added to the token's embedding. The original Transformer computed these with sine waves (the pattern shown in Lesson 3); GPT-2 learns them during training. Either way, the result has the same shape.

Shape: [5 × 768]. Each row now encodes which token and where it is.

Step 4: Run one transformer block

A transformer block is the repeating unit of the model. It has two main parts, attention and a feed-forward network. Each part is followed by two small steps: a residual connection and layer normalization.

4a. Masked multi-head self-attention. Every token builds a Query, Key, and Value, scores itself against the other tokens, and blends in the Values of the tokens that matter, exactly as in Lesson 3. GPT-2 small runs 12 attention heads side by side, each with its own 64-number Q, K, and V, and joins their outputs back into 768 numbers.

One rule is new: the attention is masked (also called causal). Each token may only look at itself and the tokens before it. " on" can attend to "The", " cat", and " sat", but not to " the". Section 6 explains why a text-generating model needs this rule.

4b. Feed-forward network. After attention has mixed context into each vector, every token's vector passes separately through the same small neural network: 768 numbers expand to 3,072, go through a nonlinear activation, then shrink back to 768. This is the multi-layer perceptron from the prerequisites, applied to one token at a time.

Attention and the feed-forward network have different jobs. Attention moves information between tokens. The feed-forward network transforms the information within each token, and it holds about two-thirds of each block's parameters. Research suggests much of the model's stored knowledge, such as facts about the world, lives in these feed-forward layers.

4c. Residual connections. Neither sub-step replaces the vector it receives. Each one computes a change that is added back onto its input:

\[ x \leftarrow x + \text{Attention}(x) \qquad x \leftarrow x + \text{FeedForward}(x) \]

This addition is a residual connection. It means information from earlier steps, such as the original word identity, is never lost; each block only adds refinements. It also gives the training signal a direct path back through many layers, which avoids the vanishing-gradient problem you saw with RNNs.

4d. Layer normalization. Every residual connection adds more numbers onto each vector, so after many blocks some values can drift very large while others stay tiny. Layers further along would then receive inputs on wildly different scales from one token to the next, which makes training unstable. Layer normalization fixes this by rescaling each token's vector on its own, in three steps:

  1. Find the mean \(\mu\) of the vector's 768 numbers.
  2. Find their standard deviation \(\sigma\), a measure of how spread out they are.
  3. Subtract the mean and divide by the standard deviation, so the numbers are centered on 0 with a spread of about 1. Then multiply by a learned scale \(\gamma\) and add a learned shift \(\beta\), which let the model adjust the range if a different one works better.
\[ \text{LayerNorm}(x) = \gamma \cdot \frac{x - \mu}{\sigma} + \beta \]

Here is the idea on a tiny 4-number vector, before the learned scale and shift:

[2, 4, 6, 8] → mean 5, standard deviation ≈ 2.24 → [−1.34, −0.45, 0.45, 1.34]

The pattern survives: the first number is still the smallest and the last is still the largest. Only the overall size changes. The word "layer" means the statistics are computed across the numbers inside one token's vector, never across different tokens, so each token is normalized independently.

Shape in: [5 × 768] → shape out: [5 × 768]

Step 5: Repeat the block 12 times

Because a block's output has exactly the same shape as its input, the output of block 1 can feed block 2, and so on. GPT-2 small stacks 12 blocks; GPT-3 stacks 96. Each block has its own learned weights, so each can learn different patterns. Studies of trained models find that earlier blocks tend to capture local patterns such as grammar, while later blocks capture broader meaning, though the split is not strict.

After the stack, the vector for " bank" in "I deposited money at the bank" would differ from the one in "We fished from the river bank". This is the context-dependent meaning that Lesson 2 promised and Lesson 3 explained.

Step 6: Turn the last vector into probabilities

To predict the next token, the model needs only the vector at the last position, " the". Because of the causal mask, that is the one position that has seen the entire prompt.

A final linear layer multiplies this 768-number vector by a matrix with one row per vocabulary token, producing 50,257 scores called logits, one for every possible next token. GPT-2 reuses the embedding table from Step 2 as this matrix, so a token scores high when the final vector points in a similar direction to that token's embedding. Softmax, the same function attention used in Lesson 3, turns the scores into probabilities that add up to 1:

\[ p_i = \frac{e^{z_i}}{\sum_{j} e^{z_j}} \]

Shape: [768] → [50,257] probabilities

Step 7: Pick a token and repeat

The model now has a probability for every token, for example " mat" high, " floor" lower, " banana" near zero. A decoding rule picks one of them. The simplest rule takes the most likely token; Section 5 covers the other options and the settings, such as temperature, that control them.

The chosen token is appended to the input, "The cat sat on the mat", and the whole pipeline runs again to predict the token after that. This loop, one token at a time, is called autoregressive generation. It stops when the model produces a special end-of-text token or reaches a length limit. A 300-word answer is roughly 400 trips through the pipeline.

The whole lesson in one line: text → token IDs → embeddings + positions → 12 × (attention + feed-forward, each with add & normalize) → last vector → logits → softmax → next token → append and repeat.

Check your understanding: shapes

Question: GPT-2 small reads the 8-token prompt "Once upon a time there lived a". What is the shape after the embedding step, after all 12 blocks, and after the final linear layer?

Answer: [8 × 768] after embedding, still [8 × 768] after the blocks, since every block keeps the shape, and [50,257] logits for the last position.

5. Choosing the Next Token: Decoding and Sampling

The model's output is a probability for every token in its vocabulary, not a single word. The rule that turns those probabilities into one chosen token is called a decoding strategy. The same model with the same probabilities can write very different text depending on this rule.

To keep things small, imagine the model only had five tokens to choose from after "The cat sat on the":

Token mat floor bed couch banana
Probability0.500.250.150.060.04

Greedy decoding

The simplest rule always picks the most likely token, here " mat". Greedy decoding is deterministic: the same prompt always produces the same output. Its weakness is that the safest choice at each step does not always add up to the best text. Greedy output tends to be bland, and it can get stuck repeating itself, because once a phrase has appeared, repeating it often looks like the most likely continuation.

Sampling

Instead of always taking the top token, sampling draws one at random using the probabilities as odds: " mat" half the time, " floor" a quarter of the time, and so on. This gives varied, more natural text, and it is why a chatbot can give different answers to the same prompt, as you saw in the first unit.

Plain sampling has its own problem: the long tail. A real vocabulary has 50,257 tokens, and most of them are poor choices with tiny probabilities. Tiny is not zero, though. If the 50,000 least likely tokens each have a probability of 0.000002, together they still hold 10% of the probability. Over a 400-token answer, a strange token is almost certain to be picked at some point, and because every chosen token is appended to the input, one bad pick can derail everything after it.

The three settings below fix this by reshaping or trimming the probabilities before the sample is drawn.

Temperature

Temperature \(T\) divides every logit by the same number before softmax is applied:

\[ p_i = \frac{e^{z_i / T}}{\sum_{j} e^{z_j / T}} \]
  • \(T = 1\) leaves the probabilities unchanged.
  • \(T < 1\) makes the gaps between logits bigger, and softmax exaggerates gaps, so the distribution gets sharper: likely tokens get even more likely.
  • \(T > 1\) shrinks the gaps, so the distribution gets flatter: unlikely tokens get more of a chance.
  • As \(T\) approaches 0, all the probability goes to the top token, which is the same as greedy decoding. This is why "temperature 0" usually means "always give the same answer".
mat floor bed couch banana
\(T = 0.5\)0.730.180.070.01<0.01
\(T = 1\)0.500.250.150.060.04
\(T = 2\)0.350.250.190.120.10

Temperature never removes a token. Even at \(T = 0.5\), " banana" still has a small chance.

Top-k sampling

Top-k sampling keeps only the \(k\) most likely tokens, sets every other probability to 0, and rescales the survivors so they add up to 1 by dividing each by their total. With \(k = 2\), only " mat" and " floor" survive, and their total is 0.75:

mat: 0.50 ÷ 0.75 = 0.67     floor: 0.25 ÷ 0.75 = 0.33

This cuts off the long tail completely. Its weakness is that \(k\) is fixed. After "The capital of France is", one token deserves nearly all the probability, yet \(k = 50\) still lets in 49 weak options. At the start of a story, hundreds of tokens might be reasonable, and \(k = 50\) throws most of them away.

Top-p (nucleus) sampling

Top-p sampling, also called nucleus sampling (Holtzman et al., 2019), fixes this by choosing how many tokens to keep based on the probabilities themselves. Sort the tokens from most to least likely, then keep the smallest group whose probabilities add up to at least \(p\). With \(p = 0.9\):

running total: mat 0.50 → floor 0.75 → bed 0.90 ✓ stop. Keep 3 tokens, then rescale: 0.56, 0.28, 0.17.

The group grows and shrinks on its own. When the model is confident, one or two tokens already reach 0.9, so few are kept. When many continuations are reasonable, the group gets large.

Putting the settings together

In practice the settings are combined: divide the logits by the temperature, apply softmax, cut the list with top-k and/or top-p, rescale, and draw a sample. Many AI tools and APIs let you set temperature and top_p directly. Common starting points look like this, although every model and product picks its own defaults:

TaskTypical settingWhy
Code, math, factual answersLow temperature (0 to 0.3)You want the most likely answer, the same way every time.
General chatTemperature around 0.7, top-p around 0.9Natural variety without wandering into the long tail.
Brainstorming, fictionTemperature 1 or higherSurprising choices are the point.
Check your understanding: decoding

Question 1: The model's probabilities are 0.95, 0.03, and 0.02. How many tokens does top-p with \(p = 0.9\) keep? How many does top-k with \(k = 3\) keep?

Answer: Top-p keeps 1, because the first token alone reaches 0.9. Top-k keeps all 3, because it always keeps exactly \(k\). This is the confident case where top-p adapts and top-k does not.

Question 2: A chatbot running at temperature 0 gives the same reply every time you ask the same question. Why?

Answer: As the temperature approaches 0, all the probability goes to the single most likely token, so decoding becomes greedy. With no randomness left, the same input always produces the same output.

6. Training and Generation Use the Same Pipeline

During generation, the model runs the pipeline once per new token and uses only the last position's prediction. During training, it runs the pipeline once on a whole passage and uses every position's prediction at the same time:

PositionThe model seesIt must predict
1The cat
2The cat sat
3The cat sat on
4The cat sat on the
5The cat sat on the mat

One six-token sentence gives five training examples at once. This is why the causal mask matters: if position 3 could attend to position 4, it could read the answer instead of predicting it. With the mask, each position only knows what came before it, which is exactly the situation the model faces when it generates text.

The model's error at each position is measured with cross-entropy loss (defined in the MLP prerequisite), which is low when the model gave the correct next token a high probability. Gradient descent then nudges every weight in the pipeline, the embedding table, every attention head, and every feed-forward layer, to reduce that loss. Processing all positions in parallel is a major reason transformers train much faster than RNNs, which must read one token at a time. The next unit, How Do LLMs Actually Learn?, picks up from here.

Check your understanding: the mask

Question: Suppose a model were trained without the causal mask on the table above. Its training loss drops close to zero, but it generates nonsense. Why?

Answer: Without the mask, each position can attend to the very next token, so the model learns to copy the answer rather than predict it. During generation the next token does not exist yet, so that shortcut is unavailable and the model has learned nothing useful.

7. Where the Parameters Live

"GPT-2 small has 124 million parameters" sounds abstract. Every one of those numbers sits in a specific box of the pipeline diagram:

Part of the pipelineCalculationParameters
Embedding table (Step 2; reused in Step 6)50,257 × 76838.6 M
Position vectors (Step 3)1,024 positions × 7680.8 M
Attention, per block (Step 4a)Q, K, V and output weights2.4 M
Feed-forward, per block (Step 4b)768 → 3,072 → 7684.7 M
All 12 blocks (Step 5)12 × 7.1 M85.1 M
Total≈ 124 M

Two things stand out. Nearly a third of GPT-2 small is the embedding table, simply because its vocabulary is large. And inside the blocks, the feed-forward networks hold twice as many parameters as attention.

Scaling up means making the same boxes bigger and repeating them more often. GPT-3 uses vectors of 12,288 numbers, 96 attention heads, and 96 blocks, for 175 billion parameters, with no new kind of box. The 1,024-position limit in the table is GPT-2's context window, the most tokens it can read at once. The next unit covers context windows and the cost of scaling in detail.

Check your understanding: parameter count

Question: A model uses vectors of 1,024 numbers instead of 768 but keeps GPT-2's 50,257-token vocabulary. How many parameters are in its embedding table?

Answer: 50,257 × 1,024 = 51,463,168, about 51.5 million.

8. Three Kinds of Transformer

Everything above describes a decoder-only transformer, the design used by GPT, Llama, and most of today’s chatbots. The same blocks can be arranged in two other ways, depending on whether the model needs to generate text, understand it, or both:

TypeAttentionGood atExamples
Decoder-onlyMasked: each token sees only earlier tokensGenerating text one token at a timeGPT, Llama
Encoder-onlyUnmasked: each token sees the whole inputUnderstanding and classifying text, searchBERT, MiniLM
Encoder-decoderEncoder unmasked, decoder masked and also attends to the encoderTurning one text into another, such as translationThe original 2017 Transformer, T5

The encoder diagrams in Lesson 3 came from the original translation Transformer, which is why they show an encoder. The blocks are the same; only the mask and the way they are connected differ.

Key Takeaways

  • A transformer is one pipeline: tokenize, embed, add positions, run a stack of identical blocks, and turn the last vector into next-token probabilities.
  • Each block pairs attention, which moves information between tokens, with a feed-forward network, which transforms each token on its own. Residual connections and normalization keep information and numbers stable through many blocks.
  • Every block keeps the shape [tokens × 768], which is what makes stacking possible.
  • Text is generated one token at a time: predict, append, repeat. The causal mask makes training match this situation.
  • A decoding strategy turns probabilities into one token. Greedy decoding always takes the top token; sampling with temperature, top-k, or top-p trades predictability for variety.
  • Bigger models use the same boxes, made wider and repeated more often.
