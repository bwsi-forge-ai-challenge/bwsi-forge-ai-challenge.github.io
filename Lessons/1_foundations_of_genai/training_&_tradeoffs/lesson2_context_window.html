Context Windows: How Much Can a Model Actually “See”?

We have already learned that transformers use attention so every token can look at every other token in the input. That mechanism is powerful, but it only works inside a fixed boundary called the context window.

This is not an abstract detail. The moment you paste a long PDF, a big codebase, or months of chat history into an API call, you hit this limit. Understanding context windows is one of the first practical constraints you will run into in your assignments and in production apps.

1. What Is a Context Window?

Remember attention from the tokens & transformers unit? Each token computes a relevance score against every other token in the sequence. That "every token sees every token" property defines what the model can reason over right now, but only within a maximum length.

Definition: The context window is the maximum number of tokens (input + output combined) a model can process in a single forward pass. Input tokens, system prompts, retrieved documents, tool results, and the model's own generated reply all count toward the same budget.

Common sizes have grown fast, but they are still finite:

  • GPT-3.5 era: ~4K tokens (roughly 3,000 words of English)
  • GPT-4 (2023): 8K or 128K variants depending on the API tier
  • Mid-2026 frontier models: many commercial APIs advertise 200K–1M+ tokens; specialized open-weight models push even higher (e.g., Llama 4 Scout at 10M advertised)

Rule of thumb English prose averages about 1.3 tokens per word. A 128K window holds on the order of ~95,000 words, a long novel, but not an entire library.

2. Why Isn't the Context Window Infinite?

The bottleneck is attention itself. Standard self-attention compares every token to every other token. For a sequence of length n, that means roughly n × n pairwise interactions, called O(n²) complexity.

Sequence length ×2 → attention pairs ×4 → compute, GPU memory, and API cost all jump sharply.
  • Compute: doubling context length roughly quadruples attention work (before optimizations)
  • Memory: attention score matrices grow with sequence length; GPUs have finite RAM
  • Cost: most APIs bill per token; longer context = higher price per request

Researchers have developed several techniques to make long contexts cheaper:

  • Sparse attention: each token attends to only a selected subset of the other tokens instead of all of them.
  • Sliding-window attention: each token attends only to a fixed number of tokens closest to it.
  • Ring attention: a long sequence is split across many GPUs, which pass their pieces around in a ring, so no single GPU has to hold the whole sequence at once.
  • KV-cache compression: while generating text, a model stores the Key and Value vectors of earlier tokens (the KV cache) so it does not have to recompute them for every new token. Compression shrinks this stored data so more tokens fit in GPU memory.

These techniques help, but they do not remove the limit. A longer context still takes more computation and more GPU memory, and both cost money. That is why every model still has a maximum context length.

3. What Happens When You Exceed the Context Window?

Behavior depends on the API and settings, but the outcome is always some form of loss:

  • Hard error: the request is rejected ("context length exceeded")
  • Silent truncation: the oldest tokens are dropped from the beginning; the model never sees them
  • Summarization middleware: your app compresses old messages before sending; quality depends on what you kept

Practical impact: a model cannot "remember" an entire long conversation, book, or codebase if it exceeds the window. That is why production systems chunk documents, summarize old chat turns, or retrieve only relevant passages that it needs.

4. Context Window vs. Actual Memory (Common Confusion)

Students often conflate two very different ideas:

Context windowPermanent "memory"
What it is Temporary working space for one API call Information stored in model weights or an external database
Changes when you chat? Fills up with tokens you send; resets each new session unless you re-send history Weights stay fixed unless the model is retrained; external DB persists until you delete it
Analogy Whiteboard in front of you right now What you learned in school (weights) + your notebook on the shelf (database)

A large context window is not the same as the model "learning" your conversation. Once the session ends (or older tokens fall off the window), that information is gone unless you stored it elsewhere. Every new conversation starts fresh with the same pretrained weights.

5. Real-World Tradeoffs

A bigger context window lets you give the model more at once: a full contract, a large part of a codebase, or a long chat history. That convenience comes with three costs.

  • Speed: the model has to read every token in the prompt before it can start replying, so a longer prompt means a longer wait. The next lesson looks at this delay in detail.
  • Money: most APIs charge per token, for both the prompt and the reply. On the most capable models, a single request that fills a 1-million-token window can cost several dollars.
  • Quality: a model that accepts 1 million tokens does not necessarily use all of them well. In one well-known study, models answered questions best when the needed information was near the start or end of a long prompt, and noticeably worse when it was buried in the middle (Liu et al., 2023). This is called the "lost in the middle" effect.

Because of these costs, well-built applications do not just send everything they have. They decide what goes into the window. A chatbot, for example, might keep the last few messages word for word, replace older messages with a short summary, include only the parts of a long document that relate to the current question, and leave enough room in the window for the model's reply.
